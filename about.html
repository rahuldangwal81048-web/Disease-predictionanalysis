About this project

Disease Prediction System is a college minor project that demonstrates how a browser-only web application can take structured user input, run it through a rule-based scoring model, and present a helpful, explainable result — all without a server, API, or database.

Why it exists

Many real-world symptom checkers are opaque "black boxes." This project takes the opposite approach: the entire dataset and scoring logic are visible, readable JavaScript, making it a good teaching example of how a simple recommendation/classification system is structured — from data modelling to UI to persistence.

How the "machine learning" style prediction works

The app does not use a trained neural network or an external ML library. Instead, it uses a transparent weighted symptom-matching algorithm, which mimics how a simple classifier would score candidates:

  1. 01

    Feature encoding. Each symptom the user selects becomes a "feature" — similar to how a real ML model encodes categorical input.

  2. 02

    Weighted scoring. Every disease in data/diseases.js stores its typical symptoms with a weight (0.1–1.0) reflecting how defining that symptom is.

  3. 03

    Coverage & noise penalty. The app calculates how much of each disease's weighted symptom profile the user's selection covers (scaled so diseases with short and long symptom lists compete fairly), then slightly penalises unrelated symptom picks.

  4. 04

    Ranking. All conditions are ranked by their final score. The top match is shown with its score as a "match score" percentage, along with up to two runner-ups. This is a measure of fit, not a probability. Symptoms such as chest tightness or shortness of breath also trigger a separate warning notice, whatever the prediction is.

Because the model lives in a single, isolated Predictor object (see js/prediction.js), it can later be replaced with a real trained ML model — for example one exported from scikit-learn to a JSON/ONNX format, or called via an external API — without changing any UI code.

Why localStorage instead of a database

This is a front-end-only demo, so there's no backend to talk to. The browser's built-in localStorage acts as a lightweight, zero-setup substitute for a database: every prediction you run is saved as a JSON record under the key diseasePredictionHistory, directly in your browser. Nothing is uploaded anywhere, and clearing your browser data will also clear your history.
